# Architecture decisions

- ADR-001: Modular Rust monolith with domain and exchange boundary crates. Additional modules follow validated workflows; avoid premature services.
- ADR-002: Rust 1.90.0, edition 2024; Node 22+ and pinned TypeScript dependencies. Commit lockfiles and use locked installs in CI.
- ADR-003: Simulation and paper are the only representable modes. No live adapter or write API in M1.
- ADR-004: Integer ticks/lots for executable values; venue scale/filter validation follows in M2. Fees stay in actual asset units.
- ADR-005: PostgreSQL for durable state; Parquet for future event datasets. Session-scoped idempotency keys and replay sequence are explicit. Ledger schema does not yet implement accounting.
- ADR-006: Node built-in HTTP server minimizes foundation dependencies. Read-only loopback API; dashboard deferred.
- ADR-007: Verified Binance official REST documentation on 2026-10-17: LIMIT_MAKER is post-only and rejected if it immediately takes liquidity. No exchange implementation is included. Revalidate current symbol filters, authentication, timeout/unknown outcomes and stream sequencing before implementing the relevant adapters.
  Source: https://github.com/binance/binance-spot-api-docs/blob/master/rest-api.md (New order / LIMIT_MAKER). This review does not establish an implemented or tested Binance integration.
- ADR-008: Starting capital is a research assumption. No live pilot until realistic net-cost validation and separate approval.

- ADR-009 (M2): A dedicated Rust public-data process owns Binance transport, order-book state, recording and replay. TypeScript reads a versioned, atomically replaced status file, avoiding exchange logic and per-request Rust subprocesses in the API. Health remains process health; market readiness is separate. A missing/bad file returns 503, and stale data clears quotes even if the collector stops.
- ADR-010 (M2): Reviewed official [WebSocket documentation](https://github.com/binance/binance-spot-api-docs/blob/master/web-socket-streams.md#how-to-manage-a-local-order-book-correctly) and [market-data-only endpoints](https://github.com/binance/binance-spot-api-docs/blob/master/faqs/market_data_only.md) on 2026-10-17. Open the stream first, buffer deltas, retrieve up to 5000 levels/side, retry snapshots older than the first buffered U, discard u <= snapshot ID, then require U <= local_id + 1 <= u. Absolute quantities replace levels; zero deletes. A gap invalidates the whole book and forces a new connection and snapshot. Ping payloads are echoed in pong frames. Connections rotate after 23 hours, before the documented 24-hour limit.
- ADR-011 (M2): Public normalized prices/quantities use exact 1e-8 units. These are data units, not executable instrument ticks/lots. BTCUSDT/ETHUSDT are the only enabled symbols. Reject unsupported precision; venue filter metadata/conversion must precede future executable orders. `DepthProtocol` separates venue decoding from normalized book/record/replay logic; existing M1 exchange traits remain unchanged. Other venues must provide their own adapter and map their sequencing semantics explicitly.
- ADR-012 (M2): Raw UTF-8 messages and normalized events share a versioned record envelope with process recording ID, connection-session UUID, record sequence and receive/exchange milliseconds. Received and applied events are distinct: buffered arrivals can precede snapshots without changing replay order. Snappy Parquet segments begin with pre-event checkpoints and carry SHA-256 sidecars. Replay verifies checksums and record continuity within each segment. No claim of total exchange history across evicted segments or independent sessions.
- ADR-013 (M2): Bound the transport queue, snapshot buffer, message size, levels and retained segments. An overflow/gap invalidates and reconnects; recording failure halts the affected symbol and removes its quotes. No silent level trimming. Complete order-book coverage is never claimed outside the initial 5000-level snapshot boundaries.
- ADR-014 (M2): Public retry defaults: 3–60 second connection backoff, at least 15 seconds between snapshot requests per symbol, and REST 418/429 Retry-After cooldown (1 second to 7 days; default 60 seconds if absent). These conservative per-process limits do not coordinate with other applications on the same public IP. TLS and artifact verification remain enabled; HTTP CONNECT proxies are supported for WSS, without proxy credential extraction.

- ADR-015 (M3): Reuse the M2 engine/Parquet replay through observer and replay-visitor hooks; add optional public aggregate-trade normalization. Support safe dynamic USDT symbols only in the scanner; keep default M2 BTC/ETH API behavior unchanged.
- ADR-016 (M3): Public `exchangeInfo` and 24-hour tickers define eligibility and collection priority; liquidity/concentration/uptime screens follow actual book observation. The economic ranking does not use trading volume as a profit signal. Default six symbols, hard cap 20, explicit resource reservations and bounded journals/observations.
- ADR-017 (M3): Manual, time-versioned and symbol-specific fee configurations only. Official [commission FAQ](https://github.com/binance/binance-spot-api-docs/blob/master/faqs/commission_faq.md) reviewed 2026-10-17: standard, tax and special commissions; maker/taker and buyer/seller components; BNB discount applies to standard components. `/api/v3/account/commission` is authenticated and was not called. No rebate/promotion/account rate is presumed. Checked u128 arithmetic and ceiling division preserve fee-asset charges; f64 is limited to descriptive research statistics.
- ADR-018 (M3): Reports remain preliminary regardless of ranking sign. One-second sampling, aggregate-trade passive-counterparty markouts and quoted depth are proxies; no own fills, queue priority, executable liquidity, profit, or daily turnover is inferred. Use conservative fee periods/cost floors and report sensitivity rather than manufacture a winner.
- ADR-019 (M3): Verify persisted online observations against the same checksum-verified replay path. Enable exact JSON float round-trip parsing; reject missing prefixes/segments or mismatched histories. Captures remain local/ignored; report audit hashes provide provenance, not remote raw-data availability.

- ADR-020 (M4): Reuse M2 replay/application and M3 fee/instrument contracts. Causal receive/application order, clamped buffered times and source sequence break ties; never reorder future books into the past. Simulated fills require an eligible post-only order, exact-price aggressive trade and queue depletion. MBP/aggregate trades cannot establish actual own execution or exact queue position.
- ADR-021 (M4): Cash-only $5,000 starts; inventory acquired via modeled fills, no shorting or borrowing. Reconcile each asset and reservation at transitions; distinguish fee/rebate, reference-relative spread capture, inventory residual, closeout estimates and observed-horizon markout attribution. Do not double-subtract markouts or count favorable inventory appreciation alone as an edge.
- ADR-022 (M4): Freeze an explicit nine-scenario grid before future OOS use. Chronological 50/25/25 split with >=60s embargo and final-test opt-in. Existing three-minute data already inspected in M3 cannot become pristine OOS retroactively; empty intervals are not validation. No parameter optimization or machine learning.
- ADR-023 (M4): Long public collection targets 24–72h with a byte-bounded rolling journal, not guaranteed archival retention. Fail closed on recording failure and explicitly flag missing prefix. Finite offline tape/trace limits reject oversized experiments; no unbounded multi-day memory allocation. Local recordings remain unarchived/ignored.

- ADR-024 (M4.1): Counters reconcile refresh opportunities, retained quotes and generated submit intents; every gate has a reason. Fee widening is separate from explicit width-cap rejection. Reached-at-exact-price, live trade-through omissions, post-cancel counterfactuals and valid queue depletion are distinct, overlapping diagnostics, never manufactured executions.
- ADR-025 (M4.1): Correct same-price own-order FIFO with cumulative queue positions and one shared observed-volume fill budget. Preserve own priority under proportional public cancellation credit. Suppress duplicate/old aggregate events; invalidate ambiguous late multi-order cancel priority. These corrections do not assert exact observable exchange queues.
- ADR-026 (M4.1): Rechecked official [aggregate-trade semantics](https://github.com/binance/binance-spot-api-docs/blob/master/web-socket-streams.md#aggregate-trade-streams) on 2026-10-17: trades aggregate a single taker order; `m` asks whether the buyer is maker. Therefore true means sell aggressor and false means buy aggressor. Controlled wire-parser tests validate both directions.
- ADR-027 (M4.1): Audit ongoing collection with two streaming replays over a frozen finalized-file list. Report observed duration, missing intervals, continuity, checksums and rolling byte budgets separately from session completion or profitable strategy readiness. Do not wait 24 hours or evaluate new OOS strategy outcomes merely to complete diagnostics.

- ADR-028 (M4.2): Initial base is lot-rounded at the first causal valid midpoint; quote residue preserves exact declared equity. Initial holdings are a portfolio reclassification, not executed purchases. All market/scenario alternatives explicitly declare capital scope; shared mode uses fixed market partitions totaling one $5,000 budget.
- ADR-029 (M4.2): Reserve principal plus configured fee assets/buffer and conservatively consider known future fee changes. Before posting a partial fill, protect remaining own and other-order reservations. Reconcile moving-average realized/unrealized P&L, fee-asset disposals and MTM equity exactly. Inventory/skew limits center on the initial base target.
- ADR-030 (M4.2): Conservative through debits entry-known intervening depth and queue ahead against eligible aggressive volume; alternative through assumes public priority cleared. Retain activation, continuity, latency, cancellation, quantity and post-only gates; fill at the own limit. One own order per side in through modes avoids unsupported multi-price counterfactual attribution. No MBP model is asserted to reconstruct exact FIFO.
- ADR-031 (M4.2): Reuse one source normalization visitor for bounded tapes and streaming batch trials. Reject affected session-symbols on integrity/coverage failures or missing tails. Persist complete traces externally and compact internal history without new ledger deposits. No aggregation of independently initialized sessions as a continuous funded portfolio; no final OOS evaluation.
- ADR-032 (M4.2): Preserve the running collector. Campaign resumption creates new immutable completed-session candidates under separate locks/roots, with count/byte budgets; never automatically take over an unfinished capture. Verify recording durations and replay scopes separately from target/elapsed wall time.


## M5: reuse the simulator for forward paper execution

Use BTCUSDT, a terminal view and the existing Engine/Observer/recorder rather than adding frontend services or another execution model. Research bypasses only the fee-derived minimum width and clamps proposed prices to the public BBA; actual configured fees and every funding/risk/execution guard remain. Economic retains fee widening but caps width at the requested setting, so insufficient settings refuse quotes. Both use conservative through execution and manual 10bps/side quote-asset fees.

Persist one isolated wallet per state directory; initialize only once from a causal book. Restart preserves balances and risk, voids virtual quotes and models no offline fills. Use an authoritative atomic checkpoint plus bounded sequenced audit journal; this engineering checkpoint does not claim an archival production OMS. No exchange execution or further milestone is authorized.


## M6: fixed hypotheses and chronological profitability screening

Reuse the funded Engine and actual M5 economic scenario; expose its internal quoting method only within the Rust crate. Compare fixed, causal volatility-adaptive, imbalance/momentum-filtered and clearly research-only touch controls. Standard 10bps/side is manual and unverified: received-asset and quote-asset costs are both tested; no favorable discount qualifies. Keep $100 clips, $500 inventory deviation and $50 drawdown controls.

Use isolated folds with no capital aggregation, 60-second embargoes and 65-second terminal settlement/markout observation. Only training nominates candidates. Validation/test cannot select or retune. A conservative inventory-neutral envelope caps net excess over initial holdings by spread capture less fees and unfavorable 60s markouts; then applies closeout stress and risk allowance. Report this separately from actual MTM and fee accounting. Insufficient/invalid data must produce an inconclusive result rather than a manufactured winner or a claim that all strategies are impossible.
